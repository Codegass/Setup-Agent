# Verification v8: three measured boundary fixes

The completed CI-anchored ten-project v6 campaign has 9/10 successful build/test executions, 8/10 CI attainment results, and 7/10 satisfying both plus the overall local success label. These sets differ: JCS completed but lacked an identity adapter; HttpCore completed and matched CI counts but retained an unresolved profile requirement; HttpClient had real test failures. Original attempts stay sealed and unchanged.

The five-project live ablation compared full v6, the legacy action interface, and mandatory planning on otherwise identical execution/evaluation code. CI attainment was 5/5, 4/5, and 5/5 respectively. The legacy DbUtils trace proves a pre-execution action/goal refusal cycle. Mandatory planning cost more tokens in this one run without increasing completion. This supports continuing with complete commands and optional plans; it does not establish a general efficiency estimate or autonomous CI-discovery capability.

V7 separately reproduced Whisker: the actual ToolResult and the agent's subsequent build claim both reported 155/155, matching the receipt and CI. The old console summary of 16 remains diagnostic. The same replay still incurred a needless refusal for a duplicate `source_command` and matching `system`.

V8 changes existing boundaries:

1. **Command-scoped Java requirements.** A current, terminal, host-authorized Maven receipt can prove explicit profile deactivation. The root POM must reproduce the surveyed Java facts and its current configuration fingerprint must match the receipt and survey. The parser then recomputes requirements with only those profiles excluded. Unknown activation, parent-derived facts that cannot be reproduced, missing authority, stale configuration, and unfinished invocations retain uncertainty. The static manifest is not rewritten. Maven documents explicit deactivation with `!` or `-`: https://maven.apache.org/guides/introduction/introduction-to-profiles.html#deactivating-a-profile.
2. **Jenkins module identities.** Each standard receipt-bound JUnit report path identifies a local module. Its tracked, unchanged POM must state a literal artifactId and groupId (including literal parent group inheritance), producing the exact Jenkins `group$artifact` namespace. Distinct modules cannot collapse to one coordinate. Full classname/testname identity and complete-pool equality remain mandatory. Property expressions, missing POMs, changed source, wrong namespaces, missing cases, and duplicates remain unscored. No global namespace stripping or artifact/directory-name heuristic is introduced.
3. **Duplicate command declarations.** A complete command may carry a matching `system` or an argv-identical `source_command`. One shared parser is used by the facade and immutable contract. It executes the complete command once, preserving the original submitted parameters in the contract. Contradictory declarations still refuse before dispatch. The legacy `action`/`args` representation is unchanged.

The regression fixtures exercise real facade receipts and publication readers with a transport/backend double. Negative cases remove authority or evidence, alter module identities and configuration, retain runtime mismatches, or interrupt execution. The focused suite passed 328 tests. The full run passed 7,567 tests with 32 skipped and one isolated packaging dependency-download failure; the network-enabled packaging recheck passed that remaining test. Together these cover 7,568 distinct passing tests, not one all-green full command. Formatting preserved every changed Python file's AST, and `git diff --check` passed. Validation logs and new live JCS/HttpCore/Whisker results are recorded outside this frozen source under `logs/verification-23-20260910/`; this source document makes no advance claim that live validation passed.

The next experiment retains the original 23 repository names. CI-anchored revision or cell changes create a new baseline, not a silently paired improvement against historical R11 tasks. Official evidence gaps, native build/test outcomes, CI attainment, and final local labels remain separate. Missing scope is unscored. Large projects run under explicit resource budgets; timeout or OOM observations cannot become an Agent success or an invented test denominator. New results and ablations remain separate attempts, with command/receipt/report/agent-observation traces retained.
