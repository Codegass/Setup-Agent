# 20 项目实验后的工具与执行修复

本轮落实四条通用修复链路：工具链观测随异步任务保存、完整输出路径传递到可见结果、失败事实进入受保护上下文、报告补交通过现有修复入口。保持原有任务、版本和 CI 范围验收规则。

## 改动及原因

1. **版本回执。** Maven、Gradle 在每次实际派发前，通过运行环境观测执行器路径和版本，并随 job obligation 保存到结算回执。结算不再通过干净控制环境重新探测历史运行版本。启动时缺少观测就保持缺失；已有观测不可在后续结算中替换。版本解析读取有界明确 banner，过滤 ANSI 和前置警告，对缺失、冲突和失败探测保留未知。JDK 继续沿用已有 dispatch probe。
2. **完整日志入口。** 后端执行只入账一次；独立的 build 外层结果也重新附加已保存输出的文件信息，并重新格式化发送给 Agent 的消息。已有内容引用和执行结果保持一致。
3. **失败上下文。** 复用已保存 receipt 中的失败诊断和用例身份，不扩充指标判定 schema。向执行器反馈及 advisor 的受保护摘要提供失败用例、断言、命令摘要和 receipt 路径；模块及 XML 哈希只在来源无歧义时附带。最多显示 8 条诊断，额外记录明确披露省略。证据入账保存的是后端结果，因此摘要同时读取已记录的执行器名称和参数，避免依赖只存在于外层结果的 `system` 字段。后台完成的失败也通过结算通知传递。小窗口分片优先保持完整行，单行超出整个窗口时仍保留原有可审计的字符分片机制。
4. **报告恢复。** report 阶段的 `report_missing` 可以开放 `report(generate)`；可用工具集合同时遵守证据封闭和当前 verdict 快照检查。模型仍需提交自己的 repair intent。报告补交不会重新开放构建或修改已封闭证据。

主要实现：[版本与回执](../../../src/sag/agent/invocation_receipts.py)、[后台任务](../../../src/sag/agent/job_obligations.py)、[引擎与可见结果](../../../src/sag/agent/react_engine.py)、[失败诊断](../../../src/sag/agent/receipt_test_rows.py)、[小窗口分片](../../../src/sag/agent/advisor_context.py)。

## 后续验证边界

本轮没有给 HTTPClient 加默认串行参数，也没有给 RocketMQ 加项目专用磁盘处理。此前消融支持的环境原因仍需由新一轮 SAG 运行验证能否自主识别和恢复。模型成功率、advisor 收益及 20 项目达标数需要新的配对运行；旧分数不会因这次修复而重写。Gradle 模块认证、Jackrabbit 全量报告归属、报告耗时等其余归因项仍在后续修复范围，官方范围缺失时继续不评分。
