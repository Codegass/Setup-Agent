# 工具输出保存与读取修复

本轮修复工具返回、持久化、公开参数和模型消息之间的连接；没有启动新的 SAG 实验。

## 已实现

- `BaseTool` 在生成预览前保留原始输出，并通过已有的输出存储绑定建立可回读的引用。成功、失败和部分完成的结果使用同一展示边界，执行状态不变。
- `OutputStorage` 保留现有 JSONL 作为引用的规范存储，为长输出提供独立 `.log` 文件。返回容器路径或明确标识的主机路径；文件内容与引用原文核对后才返回路径。文件副本不可用时保留原始 ref 的读取入口。
- 输出索引和记录读取不再经过 Docker 的展示截断，避免完整索引被裁成有效但不完整的 JSON。
- `Bash` 不再按关键词、冒号或前 50 行筛选结果。普通执行关闭上游展示截断；监控和后台执行优先使用返回的完整输出。容器初始化工具包包含 `ripgrep` 和 `sed`。
- `file_io(read)` 在文件所在环境中分页，传输有界 JSON，而不是先传整个文件再截取。保留选中内容的换行和顺序，支持超长单行续读。
- `search(ref)` 支持分页；ref 内搜索支持大小写选择、上下文、匹配偏移和真实匹配总数。公开 schema 和旧工具别名同步支持对应参数。
- 已有 ref 后补日志路径时返回新的结果对象，触发引擎重新生成模型消息。消息明确区分源输出 ref、日志文件位置和仍在增长的后台日志。
- 如果执行已结束、随后持久化失败，保留有界的执行记录，避免把存储失败误记为命令没有运行。

## 读取约定

`search(target="output_…")` 与 `file_io(action="read", path="…")` 使用相同的范围约定：

| 参数 | 含义 |
| --- | --- |
| `start_line` | 从 0 开始的行号，默认 0 |
| `end_line` | 不包含该行；省略时向文件末尾读取 |
| `column_offset` | 起始行内的字符偏移，默认 0 |
| `max_chars` | 每页正文字符数，默认 20,000，上限 100,000 |

超过预算时，返回可直接使用的 `Next read` 参数。已分页的内容豁免通用工具截断。Bash 普通长输出仍使用有界预览，并提供完整输出引用及文件路径。

ref 搜索中的 `offset` 表示跳过多少个匹配行，`context_lines` 表示匹配前后的上下文行数。容器文件也可以直接用 `rg -n -C 3` 搜索或 `sed -n` 按范围读取。

## 验证

- 新增公共工具入口与模型消息回归，覆盖长 XML 搜索结果、超长单行、Unicode/CRLF、空输出、按范围读取、大小写与匹配分页、文件写入失败、内容校验、执行追踪和存储故障。
- RocketMQ 已保存的原生日志共 5,659,714 字节，按 20,000 字符分页，283 页重组后与原文件一致。
- 原文件及重组文本 SHA-256：`3238b25867e426617808d7ad66798bf21e4aad543ef94aa393481d5f337cf293`。
- 最终回归：7,454 项通过、22 项跳过；隔离打包安装与 CLI 验证另有 1 项通过。打包测试在可联网的临时环境中完成。
- 命令、日志和源码哈希见[验证记录](2026-09-11-tool-output-repair.json)。

## 边界

此次没有修改 build/test 判定规则、CI 比较标准或 240 字符的阶段交接摘要。历史运行中已经丢失的输出不能从旧的截断引用恢复。本轮验证证明工具链路可保留和取回内容，尚未衡量修复后新的 SAG 项目完成率。
