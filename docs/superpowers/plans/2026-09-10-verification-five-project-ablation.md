# Five-project verification ablation

The owner approved this experiment on 2026-09-10. The old ten-project campaign
remains stopped. Start with commons-dbutils, commons-net, sling-commons-mime,
sling-commons-osgi, and creadur-tentacles. The owner subsequently authorized
expansion to all ten frozen benchmark projects once the five-project validation
has passed without unresolved systemic problems. Preserve the same candidate,
configuration, target definitions and attempt provenance when expanding.

## Fixed task and acceptance

Use the first five records of `benchmarks/small-ci-10-v1/manifest.json` without
changing their repository revisions, official targets, or approved local commands.
There are 5 CI modules and 1,118 final testcase records (1,116 passed, 2 skipped).
An observed count is not a terminal execution proof. Missing evidence stays
unscored. Existing attainment formulas and identity checks remain authoritative.
Repeated invocations cannot be pooled to manufacture CI coverage. Publication
exclusions already declared in the frozen benchmark remain disclosed.

Each live attempt uses the original model, reasoning, 75-iteration/1,200-second
budget, immutable Docker image, JDK/Maven versions and fresh-container policy.
Retain all attempts and actual agent-visible observations. The historical v3
results are a baseline, not a randomized contemporary control. Durations and
tokens are descriptive because dependencies and model output can vary.

## Minimal implementation

1. Add a complete-command affordance to the existing build tool. Derive the
   executor and routing metadata mechanically; preserve argv and explicit skips.
   Keep engine-owned intent/contract authorization. Do not infer success from
   the command name and do not inject test suppression.
2. Treat Analyze plans as optional, revisable guidance. Keep the physical survey
   and strict completion checks. A host-pinned acceptance command can bind actual
   receipts independently of a model-authored plan. One completed invocation may
   supply both build and test evidence. Preserve the archived plan adapter.
3. Bound report reserve relative to the whole budget so the controller can wait
   for its own jobs. Unknown terminal status still blocks a success claim.

The first real DbUtils pilot completed 523/523 passing tests but exposed two
remaining measurement defects. A terminal single-module Maven test invocation
must be able to prove compilation without an additional packaging JAR; the
existing current-receipt, contract, assessment, graph and bytecode checks remain.
Jenkins group$artifact::class#name IDs may map to raw JUnit class#name only when
both sides prove the sole module, its namespace is unique, and the full mapping
is bijective. Multiple/unknown modules, missing IDs and different testcase pools
remain unavailable. Record the identity basis; never rewrite the frozen target.
These fixes are common to every live ablation arm. Pilot verdicts are retained
as originally sealed, including the failure and unavailable score.

The v3 DbUtils pilot reached build/test success and alpha=1, but the overall
verdict was capped by a scalar Java-version equality check (compiler release 11
versus the requested CI runtime 17). Finalization now reads the same full Java
constraint range used by preflight. Upper/patch bounds, unresolved requirements,
and legacy explicit pins retain their negative controls. This fix is also common
to every final live arm; the original v3 partial verdict remains in the report.

## Experiments and reporting

The v4 five-project run produced three local successes, one partial with CI
attainment (Tentacles 2/2), and one verification failure (OSGi: native Maven
success and 28/28 archived tests, but no runner receipt through Bash). The v5
common fix routes literal Maven/Gradle Bash commands through the existing
runner while preserving the original Bash intent and command; it does not
discard environment overrides or interpret shell expressions. Unknown job
lookups return repairable lookup errors instead of fabricated pending handles.
Tentacles also exposed a local literal property (${javaVersion}=17) left
unresolved by the survey. Resolve only unambiguous unconditional local literals;
parents, profile overrides and recursive interpolation remain unknown. Preserve
all original v4 verdicts. These fixes apply equally to both ablation arms.

All five v5 tasks completed locally, but MIME's second, narrower test invocation
overwrote the XML proving its original complete CI command. Its original CI
comparison is invalid and remains unchanged. The v6 common fix captures the
original XML during receipt publication into a content-addressed, bounded store
(8 MiB per report, 64 MiB total). Later readers still verify the receipt's exact
hash and parse the original XML at its logical report path. Readers never create
snapshots; unavailable or corrupt bytes cannot substitute for evidence. Report
retention does not waive current revision, contract, assessment, terminal-state,
command, scope or identity checks. Separate invocations are never pooled. A
retention failure is visible in the tool response. Exercise an actual XML
overwrite through the strict public facade and CI adapter, plus missing/corrupt
snapshot and capacity controls, before freezing new source commits and rerunning
the five tasks and both ablations. Preserve the v5 attempt and prepared arms.

First run deterministic ablations over the five exact task commands and recorded
failure traces: old vs single-command representation; mandatory vs advisory
plan transition; fixed vs proportional report reserve. Include negative controls
for command mutation, unauthorized dispatch, wrong revision, missing terminal
receipt, explicit test skips, narrower scope, and duplicate report pools.

Then run the complete candidate on all five projects. Run independent live
leave-one-mechanism-out arms for the command and plan mechanisms on the same
five tasks. Keep the fixed task, acceptance adapter and budgets common to the
live arms so restoring a gate cannot redefine the measurement. Use source
commits rather than permanent product feature switches to freeze each arm.
If a live run exposes another defect, retain that attempt, explain the change,
and label subsequent runs as a new candidate instead of replacing results.

The final table must show CI and SAG modules; reported, passed, red, skipped,
and non-skipped tests; terminal build/test status; original alpha_build,
alpha_test and alpha; time/tokens; and reasons for every unavailable score.
Attribution must distinguish agent decisions, harness refusals, runtime faults,
and evidence failures. A single stochastic run supports case attribution,
not a population-level causal effect estimate.
