# Advisor 恢复可靠性：预先固定的消融方案

用户已同意先冻结当前修复、补齐 FreeMarker 重复对照，并要求后续修复决策必须使用消融。本轮只执行这两步，完成后总结；不自动扩大项目清单，也不在重复运行之间修改 SAG。

## 基线与范围

- 复用已经实跑的 recovery-v4 源码，完整内容与权限摘要为 `83bc9e5bfa5efa56baa2affc00f272037d350d37f2de0450ffc7e5cd87f650f1`，共 1,039 个文件。先 review、提交这些已验证的改动，并保存提交到快照的映射。无关本地产物不纳入提交。
- FreeMarker 固定 `e156e5faf9325e7ec05b781411bbf331aff98dfc`，验收任务摘要 `7aeedb7811f8ee9f35a9a955bdd62964c748eafeb903c69216f17dfd9fb68bd7`。三步依次为 Java17 主构建及测试、GraalVM21 原生编译、运行原生程序。
- 主模型 gpt-5.4-mini medium；三个实验配置分别为 advisor off、原 same-model mini（不指定 reasoning effort）、gpt-5.6-terra low。此对照比较完整 advisor 配置，不将 model 与 reasoning effort 的影响分开宣称。
- 保持已冻结的任务、目标、提示、咨询触发、64K 上下文、extractive 压缩、输出预算、迭代/时间预算、镜像和容器资源不变。
- 使用原 campaign、归档、清理和模型输入恢复工具，记录其摘要。新容器、冷依赖缓存、串行运行，先完整归档再删除本轮容器。记录实际软件 patch 版本；外部依赖或 provider 漂移不能被固定源码掩盖。

## 固定顺序

已有第一轮顺序为 off-1、mini-1、terra-1。本轮只增加六次独立运行，不承诺 provider 可复现的随机 seed：

1. mini-2
2. terra-2
3. off-2
4. terra-3
5. off-3
6. mini-3

这样三组各有三次观测，并轮换在每轮中的位置。保留所有失败、取消和不可比尝试；不得选择性重跑后替换失败。来源、预算或环境漂移单列。缺失权威归档时先处理证据问题，不把缺失当作 Agent build/test 失败。

## 指标与归因

- 首要指标：固定三步全部完成的运行数 / 尝试数；分别展示主构建及测试、原生编译、原生程序的 receipt、实际 JVM 和状态。
- 原始与去重测试的 passed/total、skipped、failed/errors；原生任务不混入 JUnit 分母。完整官方模块范围或测试身份不足时，CI 分数不可用，不凭相同计数宣称 CI 等价。
- 所有尝试的耗时和 executor/advisor/compression tokens；效率比较另按同等完整任务展示中位数和范围，不能将提前结束当作节省成本的证据。
- 保存实际模型输入、advisor 请求与回复、建议送达后的首个可证明模型调用、恢复动作及新增执行证据。工具调用失败、执行器提前结束、证据/环境问题分别归因。
- 不从工具输入输出推断模型内部想法，不从单次时间差或三个重复推导总体显著性或全项目成功率。

## 后续修复的消融约束

本轮先判断恢复行为是否重复出现，不凭单条建议或个案直接改默认模型。若多次出现“明确知道可行修复却结束”，下一轮才提出通用的恢复复核候选。每个候选须先写明失败证据、作用假设、唯一修改变量和成功/回退条件，再在相同任务与预算下比较关闭/开启。模型、咨询触发、上下文策略、结束策略不得同时改动。

只有实际完成任务增加，且未出现虚假成功、任务范围缩减、测试跳过或不可比证据的改善，才支持保留候选。零改善或有回归时保留原方案并披露结果；不叠加项目专属补丁追求绿色报告。通过后再做小项目回归和逐步扩展，另行记录实验方案。
