# 构建提示与失败诊断修复

用户授权：修正部分编译被说成整个构建成功的问题；先检查失败代码与环境，再决定修复，并做小规模消融。

## 范围

1. 复用现有 GateResult 与 TaskCompletionSnapshot。阶段提示同时说明编译证据、测试入口是否可用、固定命令的完成情况与 exit code。允许已有编译产物进入测试阶段；不改变任务验收或 CI 评分。
2. 给 executor 与 advisor 相同的有界诊断原则：从最新 settled receipt 找失败位置，阅读相关代码，测量能区分假设的环境事实，再选择修复或对照；不能凭一次失败声称稳定复现。指导不变成阻断工具的规则。
3. 保留终态优先于历史 pending 的说明。缺失诊断明确说未知；不硬编码项目修复，不自动跳过测试或修改验收命令。

## 验证

- 回归：部分编译且 package 失败、多个必需命令只完成一个、完整成功、缺证据；阶段路由和原始 receipt 不变。
- 消融：相同失败输入，比较原版、只改阶段提示、阶段提示加诊断指导。检查模型实际看到的内容和后续检查/修复选择；小样本不外推到 20 项成功率。
- 失败案例使用已有 RocketMQ、HTTPClient、Jackrabbit 材料和可复核的源码/环境对照；冻结历史报告保持不变。
